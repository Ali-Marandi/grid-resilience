# Grid Resilience Studio

**Grid Resilience Studio** یک نرم‌افزار دسکتاپ آفلاین برای غربال‌گری مهندسی تاب‌آوری شبکه‌های قدرت است. نسخهٔ `1.0.0` با یک موتور قطعی پخش بار DC، تحلیل اقتضایی N-1 برای خروج خط و ژنراتور، اعتبارسنجی مدل، رتبه‌بندی ریسک، نمایش توپولوژی و خروجی CSV قابل‌ممیزی عرضه می‌شود. این نسخه، یک محصول اولیهٔ مهندسی و آموزشی است و **جایگزین مطالعات مصوب بهره‌برداری، پخش بار AC، حفاظت یا پایداری دینامیکی نیست**.

> نتیجهٔ هر تحلیل باید همراه با کنترل کیفیت داده و بازبینی مستقل مهندسی استفاده شود. این نرم‌افزار برای فرمان یا تصمیم عملیاتی بلادرنگ طراحی نشده است.

| حوزه | قابلیت نسخهٔ 1.0.0 |
|---|---|
| تحلیل شبکه | پخش بار DC متعادل، کنترل اتصال‌پذیری، تحلیل خروج N-1 خطوط و ژنراتورها، تشخیص جزیره‌شدگی و برآورد بارِ بدون‌خدمت |
| رتبه‌بندی ریسک | شاخص شدت، بیشینهٔ بارگذاری، نقض حرارتی، برچسب وضعیت و صف نتایج مرتب‌شده |
| تجربهٔ کاربری | داشبورد محلی ویندوز، نقشهٔ شبکه با وضعیت بارگذاری، ویرایش‌گر مدل JSON و خلاصهٔ تصمیم مهندسی |
| حاکمیت داده | شناسه‌های پایدار، طرح‌وارهٔ نسخه‌پذیر JSON، اعتبارسنجی پیش از تحلیل، ذخیره‌سازی اتمیک و گزارش CSV |
| انتشار | آزمون خودکار چندنسخه‌ای پایتون، ساخت EXE مستقل ویندوز، artifact قابل دریافت و انتشار خودکار با تگ نسخه |

## شروع سریع

برای اجرای مستقیم از کد منبع به پایتون 3.11 یا جدیدتر نیاز دارید. پروژه هیچ وابستگی زمان‌اجرای خارجی ندارد.

```bash
python -m unittest discover -s tests -v
python grid_resilience_desktop.py
```

برای ساخت EXE در ویندوز، Python 3.12 را نصب کرده و فرمان‌های زیر را اجرا کنید.

```powershell
python -m pip install --upgrade pip -r requirements-build.txt
pyinstaller --noconfirm --clean --onefile --windowed --name GridResilienceStudio --collect-all tkinter grid_resilience_desktop.py
```

فایل نهایی در `dist/GridResilienceStudio.exe` ایجاد می‌شود. برای زنجیرهٔ انتشار تکرارپذیر، بهتر است از GitHub Actions استفاده کنید؛ با اجرای دستی workflow یک artifact ویندوز تولید می‌شود و با push کردن تگی مانند `v1.0.0`، workflow پس از آزمون موفق یک Release به همراه EXE و checksum SHA-256 می‌سازد.

## مدل پروژه

هر پروژه یک فایل JSON محلی با طرح‌وارهٔ `grid-resilience/1.0` است. مدل، باس‌ها، خطوط/ترانس‌ها و ژنراتورها را با شناسهٔ یکتا نگه می‌دارد. برای هر شاخه، راکتانس بر واحد و حد حرارتی موردنیاز است. برای هر باس، ولتاژ نامی، بار و یک باس slack تعریف می‌شود. دادهٔ نمونه هنگام اجرای اولیه در برنامه وجود دارد و از پنجرهٔ **Edit model data** قابل تغییر است.

| وضعیت خروجی | تفسیر |
|---|---|
| `secure` | در غربال‌گری DC نقض حد حرارتی دیده نشد. این وضعیت تأیید AC یا پایداری دینامیکی نیست. |
| `violation` | دست‌کم یک شاخه پس از رخداد از حد حرارتی اعلام‌شده عبور کرده است. |
| `islanded` | رخداد، بخش‌هایی از شبکه را از جزیرهٔ متصل به slack جدا کرده است؛ بار جداشده به‌عنوان unserved load گزارش می‌شود. |
| `unsolved` | پیکربندی پس از رخداد برای حل DC معتبر نیست؛ مانند نبود تولیدکنندهٔ آنلاین روی باس slack. |

## پایهٔ طراحی تجاری

نرم‌افزارهای تجاری تحلیل اقتضایی، خروجی‌های N-1/N-2 را با شاخص‌های امنیت ولتاژ، توان راکتیو، بارگذاری شاخه، رتبه‌بندی سریع و مقایسه با حالت پایه ترکیب می‌کنند. [1] [2] محصولات بالغ‌تر همچنین تعریف سناریوی خطا، تحلیل چندمرحله‌ای زمانی، اقدامات اصلاحی و گزارش‌های گرافیکی/جدولی را فراهم می‌کنند. [3] بنابراین این پروژه از ابتدا هستهٔ مستقل، مدل دادهٔ قابل اعتبارسنجی، شناسه‌های پایدار، خروجی قابل حسابرسی و رابط دسکتاپ را جدا کرده است تا توسعهٔ سازمانی آن قابل‌مدیریت باشد.

مدل Common Information Model در مجموعه استانداردهای IEC 61970، IEC 61968 و IEC 62325 برای تبادل‌پذیری سامانه‌های برق طراحی شده است؛ در فاز سازمانی، پشتیبانی از پروفایل CIM/CGMES باید در لایهٔ import/export پیاده‌سازی شود، نه با شکستن مدل داخلی. [4] منابع انرژی توزیع‌شده نیز نیازمند مدل‌سازی کنترل ولتاژ/توان، رفتار غیرعادی، کیفیت توان و جزیره‌شدگی هستند. [5]

## توسعهٔ امن و انتشار

Workflow موجود ابتدا آزمون‌های واحد را روی Python 3.11 تا 3.13 اجرا می‌کند، سپس روی runner ویندوز EXE می‌سازد. تنها تگ‌هایی با الگوی `v*` مسیر انتشار را فعال می‌کنند. قبل از انتشار عمومی باید release notes، نسخه، checksum، وضعیت آزمون‌ها و سیاست مجوزدهی بازبینی شوند. برای نسخهٔ تجاری، امضای کد Authenticode، SBOM، اسکن وابستگی، SAST و کلیدهای انتشار محافظت‌شده نیز باید اجباری شوند.
